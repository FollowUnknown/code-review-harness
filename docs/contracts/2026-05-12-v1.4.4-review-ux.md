# Contract: v1.4.4 评审执行体验优化

> 日期: 2026-05-12
> 状态: review_pending
> 类型: Business Task
> 版本: v1.4.4

## 背景

当前三种评审类型（MR、Local、多工程）的 SSE 流都只推送步骤进度（扫描中 → 分类中 →
评审中 → 完成），报告在全部批次完成后一次性返回。当评审较多文件时：

- 用户全程看转圈，体验极差
- 中途关闭页面所有结果丢失，无法恢复
- 无法中断长时间运行的评审（多工程评审可能跑几十分钟）
- 三种评审各自内联了相同的 SSE + 批处理逻辑，缺少统一的暂停/恢复能力

v1.4.4 统一解决：每次批处理完立即推送部分结果，并支持暂停/断点恢复。

## 方案

### 共享架构抽取

```
当前（三份重复）:
  review.ts          — 内联 sendSSE / batch loop / ProgressEvent
  review-local.ts    — 内联 sendSSE / batch loop / ProgressEvent
  review-requirement.ts — 内联 sendSSE / batch loop / ProgressEvent

目标（抽取共享）:
  src/server/services/
  ├── sse-helper.ts            — sendSSE() / nextStep() / completeStep()
  ├── review-pause-controller.ts — shouldPause Map / checkAndPause()
  └── review-checkpoint-store.ts — CRUD

  review.ts          — import { sendSSE, ... } from sse-helper
  review-local.ts    — import { sendSSE, ... } from sse-helper
  review-requirement.ts — import { sendSSE, ... } from sse-helper
```

### SSE 事件流变更（三种评审统一）

```
当前:  step events (running/done/error) -> COMPLETE(一次性全部 report)

目标:  step events (running/done/error)  // 保留，向后兼容
       + review_start({reviewType, totalBatches, totalFiles})  // 新增
       + batch_result({batchIndex, files, issues, progress}) x N  // 新增
       + paused({checkpointId, progress})            // 新增，暂停时
       + resumed({checkpointId, remainingBatches})   // 新增，恢复时
       + COMPLETE(final_report)       // 保留，逻辑不变
```

### 暂停/恢复流程（三种评审统一）

```
暂停:
  1. 用户点暂停 -> POST /api/review/pause { jobId }
  2. pause-controller 设 shouldPause(jobId) = true
  3. 当前批次完成后 -> saveCheckpoint() -> SSE emit paused
  4. 前端显示"已暂停，可恢复或放弃"

恢复:
  1. 用户点恢复 -> POST /api/review/resume { checkpointId }
  2. 加载 checkpoint -> 重新扫描+分类 -> 跳过已完成批次
  3. SSE emit resumed -> 继续 batch_result 流
  4. 前端在已有结果上追加
```

### 数据库

```sql
CREATE TABLE IF NOT EXISTS review_checkpoints (
  id              TEXT PRIMARY KEY,
  review_type     TEXT NOT NULL CHECK(review_type IN ('mr', 'local', 'requirement')),
  project_id      TEXT NOT NULL,
  source_branch   TEXT,
  target_branch   TEXT,
  status          TEXT NOT NULL DEFAULT 'running'
    CHECK(status IN ('running', 'paused', 'completed', 'abandoned')),
  current_batch   INTEGER DEFAULT 0,
  total_batches   INTEGER DEFAULT 0,
  total_files     INTEGER DEFAULT 0,
  reviewed_count  INTEGER DEFAULT 0,
  batch_results   TEXT DEFAULT '[]',
  accumulated_scores TEXT DEFAULT '[]',
  accumulated_stats TEXT DEFAULT '{}',
  job_id          TEXT,
  created_by      TEXT,
  created_at      TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_rc_review_type ON review_checkpoints(review_type);
CREATE INDEX IF NOT EXISTS idx_rc_project ON review_checkpoints(project_id);
CREATE INDEX IF NOT EXISTS idx_rc_status ON review_checkpoints(status);
CREATE INDEX IF NOT EXISTS idx_rc_project_status ON review_checkpoints(project_id, status);
```
