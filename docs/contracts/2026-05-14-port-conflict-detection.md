# Contract: 服务器启动端口冲突检测

> 日期: 2026-05-14
> 状态: completed
> 类型: Business Task
> 版本: v1.4.9

## 背景

当前 `src/server/index.ts` 直接调用 `app.listen(PORT)` 启动服务器，没有端口冲突检测机制。如果端口已被占用，Node.js 抛出 `EADDRINUSE` 导致进程崩溃，用户看到的是未处理的异常堆栈，体验差。

## 范围

### 改动文件
- `src/server/index.ts` — 修改 `app.listen` 逻辑，增加端口冲突检测与友好错误处理

### 行为
1. 启动时监听 `EADDRINUSE` 错误事件
2. 端口冲突时输出清晰的中文错误提示，包含端口号和建议操作
3. 进程以非零退出码退出（exit code 1）
4. 正常启动行为不变

### 不做
- 不做自动端口递增（避免隐式行为导致前端 API 地址不匹配）
- 不修改端口配置方式（仍然从 `process.env.PORT` 读取，默认 3001）
- 不涉及测试文件改动（启动逻辑变更，手动验证即可）

## 验收标准

- [ ] 端口空闲时，服务器正常启动，日志不变
- [ ] 端口被占用时，输出友好的中文错误提示并退出
- [ ] 退出码为 1
- [ ] 不引入新依赖
