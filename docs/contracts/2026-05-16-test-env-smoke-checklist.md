# Contract: 测试环境部署步骤与冒烟检查清单

> 日期: 2026-05-16
> 状态: completed
> 类型: Platform Task
> 版本: v1.4.9

## 背景

即使完成构建、配置、数据库和拓扑设计，如果没有统一的部署步骤与冒烟验证清单，测试环境仍然可能在“部署成功”的表象下遗留大量不可见问题，例如登录失败、repo mapping 缺失、GitLab 预览不可用、LLM 不通、暂停恢复失效等。

需要把上线前和上线后的检查动作固化成可重复执行的 checklist。

## 范围

### 改动对象

- 测试环境部署文档
- 冒烟检查清单
- 必要时补充辅助脚本或验证命令说明

### 目标行为

1. 明确从拉代码、安装依赖、配置环境变量、初始化数据到启动服务的完整步骤
2. 明确测试环境首次上线后的冒烟顺序
3. 覆盖登录、静态资源、GitLab 预览、需求评审、SSE 进度、暂停恢复、报告查看等关键链路
4. 给出失败时的定位入口和回退策略

## 不做

- 不在本 Contract 内新增业务自动化测试框架
- 不要求一次性覆盖所有边缘场景
- 不在本 Contract 内实现 CI/CD

## 验收标准

- [ ] 有完整的部署步骤清单
- [ ] 有关键链路冒烟检查清单
- [ ] 有失败定位入口与回退建议
- [ ] 文档可供后续新同事独立执行

## 架构确认（2026-05-16）

### 冒烟顺序

1. 环境检查：端口、进程、数据库路径、`KNOWLEDGE_DB_PATH`
2. 静态资源检查：`/` 能打开、前端 JS/CSS 可加载
3. 身份检查：`/api/auth/status`、登录/刷新 token
4. 数据检查：`/api/review/...`、`/api/reviews/...`、`/api/llm/settings/llm`
5. 配置检查：GitLab/LLM/蓝湖相关接口
6. 流式检查：SSE 评审过程能持续推送、不中断
7. 数据同步检查：本地基线库同步、目标库备份、`schema_version`
8. 回滚检查：恢复备份后服务仍可启动

### 场景覆盖

- 首次部署
- 版本升级
- 目标库覆盖前备份
- SSE 长连接中断后的恢复
- LLM 连通性异常
- GitLab token 缺失/错误

### 失败定位入口

- 反代错误：Nginx / 网关日志
- 启动失败：应用控制台日志
- 数据库问题：`db:sync-test-env` 输出与 fingerprint
- LLM 问题：`/api/llm/settings/llm/check`

### 边界

- 不在 G5 内新增自动化 CI
- 不在 G5 内覆盖所有边缘故障
- 不在 G5 内替代手工验收
