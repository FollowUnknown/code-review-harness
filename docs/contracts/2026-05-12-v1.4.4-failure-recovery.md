# Contract: v1.4.4 评审失败/断网时保留已完成批次记录

> 日期: 2026-05-12
> 状态: completed
> 类型: Business Task
> 版本: v1.4.4

## 背景

评审运行过程中，如果出现 LLM 错误或网络断开：
1. 服务端 checkpoint 只在暂停时保存 batchResults，每批次不增量更新
2. SSE 断开后 60s timeout 将 checkpoint 标记为 `abandoned`
3. 刷新页面后，客户端只查询 `status=paused` 的 checkpoint，`abandoned` 的被忽略
4. 用户看到的是空白——所有已完成批次的评审记录全部丢失

## Grading Criteria

### G1: 服务端每批次增量保存 checkpoint (P0)
- 每完成一个 batch 后，立即调用 `updateCheckpoint` 写入 `currentBatch`、`reviewedCount`、`batchResults`
- 涉及 `review-local.ts`、`review.ts`、`review-requirement.ts` 三个路由
- 不额外增加 LLM 调用，SQLite 写入 <1ms

### G2: SSE 断开标记为 "interrupted" 替代 "abandoned" (P0)
- `CheckpointStatus` 类型新增 `"interrupted"` 状态
- `res.on("close")` 60s timeout 改为 `updateCheckpoint(id, { status: "interrupted" })`，不再调用 `abandonCheckpoint`
- `interrupted` 表示"非正常中断，但有可恢复数据"

### G3: 客户端刷新后恢复 interrupted checkpoint (P0)
- mount 时的 checkpoint 查询改为 `status=paused,interrupted`（或两次查询）
- interrupted checkpoint 显示已完成批次的 issues/scores
- 标题显示"评审中断"提示
- 提供 Resume 和 Abandon 按钮（同 paused 逻辑）

### G4: 客户端 SSE error 事件处理 (P1)
- 三个页面的 SSE 循环中增加 `event.status === "error"` 处理
- 收到 error 时：保留已有 batchResults 不清除，设置 error message
- ReviewProgress 组件继续显示已完成批次
