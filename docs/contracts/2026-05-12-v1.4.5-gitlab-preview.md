# Contract: v1.4.5 需求评审 Preview 改用 GitLab API

> 日期: 2026-05-12
> 状态: completed
> 类型: Business Task
> 版本: v1.4.5

## 背景

需求评审 Preview 接口 (`POST /requirement/preview`) 当前耗时 3 分钟+，因为 `buildMultiProjectScanContext` 对每个工程执行完整 5 步扫描（git diff + AST + 符号提取 + 关联文件搜索 + 文件读取），而 Preview 只需要文件列表和 diff 统计。

每个产品线下的项目已配置 `localPath`（本地仓库路径），但未配置 GitLab 地址。如果加上 GitLab 项目信息，Preview 可直接调 GitLab Compare API，无需本地 git 操作。

## 方案

### Preview 新流程（替代 `buildMultiProjectScanContext`）

```
getRepoMappingsByProductLine → [{project, localPath, gitlabHost, gitlabProjectPath}]
    ↓
过滤：有 gitlabProjectPath 的项目用 GitLab API，没有的 fallback 本地
    ↓
并行调 GitLab Compare API：
  GET /api/v4/projects/:encoded_path/repository/compare?from=target&to=source
    ↓
从返回的 diffs 提取：文件列表、diff 大小、推断技术栈
无 diff / 分支不存在的项目跳过
    ↓
Token 估算：diff chars / 4（粗估，与 Review 阶段精算误差 <20%）
    ↓
返回 {projects, totalFiles, totalTokens, projectCount}
```

### Review 阶段

Review 仍用 `buildLocalScanContext`（需要 AST + 关联文件，GitLab API 拿不到）。
但 `extractLocalDiff`（步骤 1）可改为优先从 GitLab API 拿 diff，省掉本地 git diff 耗时。

## Grading Criteria

### G1: repo_mappings 表新增 GitLab 字段 (P0)
- `gitlab_host` TEXT：GitLab 实例地址（如 `https://gitlab.example.com`）
- `gitlab_project_path` TEXT：项目路径（如 `group/qiqiao-api`）
- DB 迁移：ALTER TABLE 加字段（nullable，不影响已有数据）
- `RepoMapping` 类型 + CRUD 适配
- Settings 页面项目配置支持填写 GitLab 地址

### G2: Preview 改用 GitLab Compare API (P0)
- 新增 `fetchCompareDiffsForBranches(host, projectPath, sourceBranch, targetBranch, token)`
- Preview 路由：有 GitLab 配置的项目走 API，没有的 fallback 本地 `buildLocalScanContext({skipHeavy: true})`
- GitLab API 错误（分支不存在、404）视为无 diff，不阻断
- Preview 耗时从 3 分钟降到 30 秒内

### G3: Review 阶段 diff 来源可选 GitLab API (P1)
- `buildLocalScanContext` 新增 `gitlabDiffs` 参数：如果外部已拿到 diffs，跳过步骤 1
- Review 路由：优先从 GitLab API 拿 diff，传入 `buildLocalScanContext`
- 拿不到时 fallback 本地 git diff

### G4: Token 来源 (P0)
- 优先 `process.env.GITLAB_TOKEN`
- 未配置时，Preview 请求体可传 `gitlabToken`
- 前端：环境变量未配置时在 Preview 表单显示 GitLab Token 输入框
