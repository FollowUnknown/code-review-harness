# Contract: v1.4.4 恢复流程 + 测试覆盖（B4/B5/B11/B13/G3）

> 日期: 2026-05-12
> 状态: completed
> 类型: Business Task
> 版本: v1.4.4

## 背景

v1.4.4 的暂停基础设施（types、DB、SSE events、pause-controller、checkpoint-store）已完成，但核心恢复链路未打通：
- `POST /api/review/resume` 仅返回 JSON，未建立 SSE 重连
- 无跳过已完成批次的逻辑
- 页面重载后不检测 paused checkpoint
- SSE 关闭超时 30s，仅标记 job aborted，不标记 checkpoint abandoned
- 5 个新模块零测试覆盖

## 范围

### 做

**B13 — 60s 超时 + auto-abandon**
1. `review-local.ts` / `review.ts` / `review-requirement.ts`：`abortTimeout` 30s → 60s
2. 超时回调中增加 `abandonCheckpoint(checkpointId)` 调用
3. `review.ts` / `review-requirement.ts`：`checkpointId` 变量提升至外层作用域

**B4/B5 — 恢复流程 + 跳过已完成批次**
1. `src/shared/types.ts`：`LocalReviewRequest`、`ReviewRequest` 增加可选 `checkpointId`
2. 三个 route 接受 `checkpointId`：
   - 加载 checkpoint，校验 `status === "paused"`
   - 正常扫描/分类/知识库加载（LLM 评审需要原始 diff）
   - emit `resumed` SSE event
   - 从 `checkpoint.batchResults` 恢复已完成的 batchReports
   - batch 循环从 `currentBatch` 开始，跳过已完成批次
3. 需求评审 (`review-requirement.ts`)：通过 `accumulatedStats` 恢复项目索引位置

**B11 — 前端页面重载检测**
1. `LocalReviewPage.tsx`：mount 时查询 `GET /api/review/checkpoints?status=paused&review_type=local`，恢复暂停状态和 UI
2. `ProgressStepper.tsx`（MR 页面）：同上，`review_type=mr`
3. `RequirementReviewPage.tsx`：同上，`review_type=requirement`
4. 三页面 `handleResume` 更新为调用 review POST 端点并附带 `checkpointId`

**G3 — 测试覆盖**
1. `tests/server/services/review-pause-controller.test.ts` — 新建
2. `tests/server/services/review-checkpoint-store.test.ts` — 新建
3. `tests/server/services/sse-helper.test.ts` — 新建
4. `tests/server/routes/review-checkpoint-routes.test.ts` — 新建

### 不做

- 不创建独立 resume 端点（复用现有 POST 端点 + `checkpointId` 参数）
- 不改变现有无暂停操作的评审行为（向后兼容）
- 不做 checkpoint 自动清理
- 不改变 LLM 调用逻辑或 prompt 结构

## Grading Criteria

- [ ] B4: resume 端点建立 SSE，emit `resumed`，继续 `batch_result` 流
- [ ] B5: 恢复后从 `currentBatch` 开始，不重复评审已完成批次
- [ ] B11: 三页面 mount 时检测 paused checkpoint，展示恢复选项
- [ ] B13: SSE 关闭 60s 后标记 checkpoint `abandoned` + job `aborted`
- [ ] G3: 4 个新测试文件通过，新增模块覆盖率 >= 80%
