# Contract: v1.4.6 需求评审记录管理 + 暂停恢复

> 日期: 2026-05-13
> 状态: in_progress
> 类型: Business Task
> 版本: v1.4.6

## 背景

当前需求评审完成后才写入 `reviews` 记录，评审过程中列表页看不到进度。暂停/恢复只能在 SSE 页面操作，刷新后虽然有 checkpoint 恢复，但体验不连贯。需要：
1. 评审开始即创建记录，过程中实时更新
2. 统一评审列表支持需求评审类型
3. 暂停/恢复状态在记录详情中可操作
4. 项目级详情复用现有 MR 评审组件

## 方案

### 核心思路：需求评审记录 = 一条 reviews 记录 + N 条子项目记录

```
reviews 表（主记录）
├── id: "R-xxxx"
├── mr_url: "requirement://产品线ID/source..target"
├── status: "reviewing" | "completed" | "paused" | "interrupted"
├── report_json: RequirementReviewReport（随项目完成逐步填充）
└── product_line_id: 产品线ID

review_sub_reports 表（子项目记录，新增）
├── id: 自增
├── review_id: "R-xxxx"（关联主记录）
├── project: "do1cloud-form"
├── tech_stack: "java-backend"
├── status: "pending" | "reviewing" | "completed" | "failed"
├── report_json: ReviewReport（单个项目的评审结果）
├── classification_json: ClassificationSummary
├── score: 平均分
├── issue_count: 问题数
└── created_at / updated_at
```

### 评审流程改造

```
POST /requirement
    ↓ 立即创建 reviews 主记录（status: reviewing）
    ↓ 返回 SSE 事件中带 reviewId
    ↓ 逐项目评审：
    │   开始项目 → 创建 sub_report（status: reviewing）
    │   项目完成 → 更新 sub_report（status: completed, report_json）
    │   同时更新主记录的 report_json（增量合并）
    ↓ 暂停 → 主记录 status: paused，前端可从记录恢复
    ↓ 全部完成 → 主记录 status: completed
```

### 前端页面

1. **评审列表页**（已有 `/reviews`）：支持需求评审类型展示
2. **需求评审详情页**（新增 `/requirement-review/:id`）：展示子项目列表 + 暂停/恢复操作
3. **项目详情**：复用现有 MR 评审详情组件

## Grading Criteria

### G1: 数据层 — 子项目记录表 (P0)
- 新增 `review_sub_reports` 表
- `ReviewSubReport` 类型定义
- CRUD：createSubReport, updateSubReport, listSubReports(reviewId)
- reviews 表 `status` 字段新增 `reviewing` / `paused` / `interrupted` 状态

### G2: 评审流程改造 — 实时写记录 (P0)
- `review-requirement.ts`：评审开始时立即 `saveReviewRecord`（status: reviewing）
- 逐项目完成时：创建/更新 sub_report + 增量更新主记录 report_json
- 暂停时：主记录 status → paused
- 完成时：主记录 status → completed
- SSE 新增事件：`review_created`（带 reviewId，前端可立即跳转）

### G3: 评审列表页支持需求评审 (P0)
- 现有评审列表页增加需求评审类型
- 显示：产品线名、分支、状态（评审中/已暂停/已中断/已完成）、总分
- 评审中的记录显示进度条（已完成项目数/总项目数）

### G4: 需求评审详情页 (P0)
- 新路由 `/requirement-review/:id`
- 展示子项目列表：项目名、技术栈、状态、分数、issue 数
- 评审中/已暂停/已中断状态显示恢复按钮
- 点击项目 → 跳转项目详情（复用 MR 评审详情组件）

### G5: 暂停/恢复在记录中体现 (P1)
- 详情页显示暂停/恢复/放弃按钮
- 恢复操作：从 checkpoint 恢复评审，继续 SSE 流
- 状态实时同步（SSE 事件或轮询）
