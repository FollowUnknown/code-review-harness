> 日期: 2026-05-16
> 状态: completed
> 类型: Platform Task
> 版本: v1.4.9

## 背景

测试环境运行不仅依赖 `PORT`，还依赖 `GITLAB_TOKEN`、LLM Provider 配置、可能的蓝湖配置，以及前后端对这些配置的实际读取方式。当前 `env.example` 只覆盖部分变量，且缺少对配置优先级、可选项、默认值和部署方式的统一说明。

这一块同时涉及密钥与配置红线，必须单独建 Contract。

## 范围

### 改动对象

- `env.example`
- 配置读取相关代码与文档
- 测试环境部署文档中的环境变量章节

### 目标行为

1. 列出测试环境必填、选填、仅本地开发使用的环境变量
2. 明确每个变量的用途、默认值、优先级、缺失后的降级行为
3. 统一密钥管理约定，避免 token 散落在请求体、数据库和部署脚本中没有边界
4. 明确 GitLab / LLM / 蓝湖等外部依赖的连通性要求

## 不做

- 不在本 Contract 内修改评审业务逻辑
- 不在本 Contract 内处理数据库结构调整
- 不在本 Contract 内引入新的密钥管理平台

## 验收标准

- [ ] 测试环境环境变量清单完整
- [ ] `env.example` 与实际代码读取逻辑一致
- [ ] 必填密钥、可选密钥、默认值边界清晰
- [ ] 配置与密钥部分有单独审查记录

## 架构确认（2026-05-16）

### 对象

- **基础运行配置**：`PORT`、潜在的前端端口说明
- **GitLab 配置**：`GITLAB_HOST`、`GITLAB_TOKEN`
- **LLM 配置**：`LLM_PROVIDER`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL`、`DEEPSEEK_API_KEY`
- **扩展集成配置**：`LANHU_TOKEN`、`LANHU_BASE_URL`
- **超时类配置**：`REVIEW_TIMEOUT_MINUTES`

### 配置分层

```
代码默认值
   ↓
环境变量
   ↓
DB settings（仅用于运行期可编辑项）
```

### 设计决策

1. 测试环境文档必须区分“部署前必须写入环境”的配置与“运行后可在 UI/DB 中修改”的配置
2. `env.example` 不是随意示例，而是测试环境最小可运行配置模板，必须与代码读取逻辑对齐
3. 密钥优先走环境变量；请求体临时传 token 的能力视为补充通道，不作为测试环境主路径
4. 所有外部依赖配置都要写明“缺失时系统表现”，避免部署后只能靠报错反推

### 边界

- 不在 G2 内引入新的 Secret Manager
- 不在 G2 内修改 GitLab / LLM 业务逻辑
- 不在 G2 内处理数据库迁移细节
