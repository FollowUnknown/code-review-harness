# Contract: v1.4.4 暂停/恢复 UX Bug 修复

> 日期: 2026-05-12
> 状态: review_pending
> 类型: Business Task
> 版本: v1.4.4

## 背景

v1.4.4 暂停/恢复功能已实现，但用户反馈以下问题：

1. **暂停按钮无即时反馈**：点击暂停后按钮不变为 Resume，评审继续运行（LLM 批次处理可能 30-60s，暂停只在批次间隙生效）
2. **刷新后丢失暂停状态**：刷新页面后看不到已暂停的评审内容
3. **无统一入口查看未完成评审**：用户不知道去哪里找未完成的需求多工程评审

## Grading Criteria

### G1: 暂停按钮即时反馈 (P0)
- 点击暂停后，按钮**立即**变为禁用态（"暂停中..."）
- 不需要等服务端确认，客户端先切换视觉状态
- 服务端完成暂停后，按钮变为 Resume + Abandon

### G2: 刷新后恢复暂停状态 (P0)
- 刷新需求评审页面后，如果存在 paused checkpoint，**自动恢复**：
  - ReviewProgress 显示已完成批次的 issues/scores
  - 按钮显示 Resume + Abandon
- 刷新本地评审页面后，同上
- `checkActiveJob` 和 `checkPausedCheckpoints` 不应互相干扰

### G3: 暂停状态可靠检测（polling 模式） (P0)
- polling 模式下，`job.status === "paused"` 时：
  - 停止 polling
  - 查询 checkpoint 恢复 batch 级进度
  - 显示 Resume + Abandon 按钮

### G4: 暂停请求乐观更新 (P1)
- 暂停请求发送后，客户端不再重复发送（防抖）
- 如果暂停失败（网络错误），按钮恢复可点击状态
