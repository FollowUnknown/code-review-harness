# v1.6.0 - 知识库深度优化

> 状态: 待规划
> 前置: v1.5.0 (评审质量度量与提升)
> 后置: v1.7.0

## 背景

知识库已有基础 CRUD 和评审注入能力，但存在以下痛点：
- 知识依赖人工录入和评审自动提取，覆盖度不够
- 不同技术栈的知识边界模糊
- 知识被评审"采纳"后缺少有效性回归验证
- DEPRECATED 条目生命周期管理不完整
- **当前基于关键词/SQL 匹配，无法语义搜索** — "RESTful 规范" 搜不到 "API 设计"

## 核心目标

1. **知识覆盖度提升** — 自动从代码中提取隐性知识
2. **知识有效性可验证** — 被采纳的知识有回归追踪
3. **跨技术栈知识边界清晰** — 知识按技术栈精确匹配
4. **向量/文件知识库** — 语义搜索替代关键词匹配，知识图谱持久化可 Git 共享

## 技术探索：向量知识库 + Graphify

### 向量化方案
- SQLite 向量扩展（sqlite-vec）或独立向量库（Chroma/Qdrant），避免重型依赖
- 本地 ONNX 嵌入模型（all-MiniLM-L6-v2），不依赖外部 API
- PoC 验证：对现有 371 条知识做向量化，对比关键词 vs 语义搜索召回率

### Graphify — 跨模态知识图谱
- 定位：代码 + 文档 + 图片统一知识编译器
- 产出：graph.html（交互式图谱）、graph.json（持久化数据），可提交 Git 团队共享
- Token 效率：查询比逐次读原始文件节省 ~71.5x
- 集成方式：Skill 触发图谱构建/查询

## 功能清单

### 1. 知识有效性回归
- [ ] 被评审采纳的知识，后续评审是否继续被采纳（hit rate 趋势）
- [ ] 长期未被采纳的 CONFIRMED 知识自动标记为待验证
- [ ] 知识有效性仪表盘：命中率、最后一次命中时间、贡献度排名

### 2. 知识自动提取增强
- [ ] 从 AST 分析中提取结构性知识（函数签名变更模式、常用依赖）
- [ ] 从评审 issue 中提取重复模式 → 建议创建知识条目
- [ ] 代码规范文件（.eslintrc、checkstyle.xml）自动导入为知识

### 3. 跨技术栈知识管理
- [ ] 知识条目标记适用技术栈（而非仅按 project）
- [ ] 评审时按实际文件技术栈筛选知识，避免前端知识注入后端评审
- [ ] 技术栈知识冲突检测与合并建议

### 4. 知识生命周期完善
- [ ] CONFIRMED → 待验证 → DEPRECATED 的完整流程
- [ ] 定期知识清理：重复检测、过期标记、低质量建议删除
- [ ] 知识版本历史（修改可追溯）

## 验收标准
- [ ] 知识覆盖率提升：评审中知识命中率 > 60%
- [ ] 无效知识（长期未命中）自动识别
- [ ] 跨技术栈注入误配率 < 5%
