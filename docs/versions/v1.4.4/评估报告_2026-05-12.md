## 📋 设计文档概述

v1.4.4 包含两个核心功能：
1. **逐步评审报告** — 每批文件评审完立即推送结果，不等全部结束
2. **暂停/重启** — 长时间评审可暂停，保存检查点，重启时从断点继续

## 🔧 关键待办

### P0 - 核心链路必须完成

1. **review-local.ts 暂停流程串联**
   - 在批次循环开始处添加 `isPauseRequested()` 检查
   - 暂停时：保存当前 `batch_results` 到 checkpoint、发送 `paused` SSE 事件、更新 checkpoint 状态为 `paused`

2. **resume 路由实现续评逻辑**
   - 从 checkpoint 加载已完成的批次结果
   - 建立 SSE 连接
   - 发送 `resumed` 事件
   - 跳过已完成批次，从断点继续评审
   - 前端追加已有结果并继续渲染

3. **LocalReviewPage 集成暂停/恢复按钮**
   - 传入 `onPause`/`onResume`/`onAbandon` 回调
   - 实现暂停请求（POST /api/review/pause）
   - 实现恢复请求（POST /api/review/resume）
   - 实现放弃请求（DELETE /api/review/checkpoints/:id?abandon=true）

### P1 - 配套功能

4. **新建检查点列表组件/页面**
   - 展示所有 paused 状态的检查点
   - 支持从检查点恢复评审
   - 支持放弃/删除检查点

5. **添加并发检查点限制**
   - 每个用户/项目最多 3 个并发检查点
   - 超出时拒绝新的检查点创建

### P2 - 边界处理

6. **处理"待讨论"问题**
   - 暂停后源分支代码变更了怎么处理
   - 多用户同时评审同一项目时的检查点隔离
