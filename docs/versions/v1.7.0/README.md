# v1.7.0 - 开发者评审闭环

> 状态: 待规划
> 前置: v1.6.0 (评审质量度量)
> 后置: v2.0.0

## 背景

评审结果目前只有评审发起者能看到，研发人员收到评审后：
- 不知道具体哪里出问题（文件/行号不够直观）
- 不知道如何修复（只有 suggestion 文本）
- 修复后没有复审流程，无法确认问题已解决

## 核心目标

1. **问题定位精准** — 研发能快速定位到具体代码位置
2. **修复建议可操作** — 不只是"建议修改"，而是具体怎么改
3. **复审流程闭环** — 修复后能触发复审，确认问题已解决

## 功能清单

### 1. 评审结果展示优化
- [ ] Issue 与 diff 行号关联，点击跳转到具体代码位置
- [ ] Issue 分组展示：按文件/按严重级别/按类型
- [ ] 关联知识条目展示（为什么报这个问题，依据是什么）
- [ ] 评审结果分享链接（无需登录可查看）

### 2. 修复引导
- [ ] Issue 修复建议增强：从"建议"到"示例代码"
- [ ] 常见问题模板：已知模式的修复方案库
- [ ] 一键创建 fix 分支（基于 issue 自动生成修复分支名）

### 3. 复审流程
- [ ] 开发者标记 issue 状态：已修复/拒绝（附理由）/重新评审
- [ ] 全部 issue 处理完后触发复审（只看之前报的 issue 是否解决）
- [ ] 复审结果与原始评审关联对比
- [ ] 复审通过后自动标记评审状态为 passed

### 4. 评审通知集成
- [ ] 评审完成后通知相关开发者
- [ ] Issue 分配给对应代码的作者（基于 git blame）
- [ ] 复审请求通知评审发起者

## 验收标准
- [ ] 研发人员能独立理解评审问题，无需口头沟通
- [ ] 复审流程端到端可用
- [ ] 评审结果分享链接可用
