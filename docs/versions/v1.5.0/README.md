# v1.5.0 - 评审质量度量与提升

> 状态: 待规划
> 前置: v1.4.3 (Java 评审经验知识导入)
> 后置: v1.6.0

## 背景

评审质量目前靠主观感受，缺少量化指标：
- LLM 看到的上下文有限（diff + 关联文件 + AST，没有运行时信息）
- 评分维度固定，不能根据变更类型动态调整
- 误报率没有追踪，不知道哪些 issue 是误报
- 无法对比不同 prompt/知识配置下的评审质量差异

## 核心目标

1. **评审质量可量化** — 建立评分体系，追踪质量趋势
2. **上下文质量提升** — 给 LLM 更精准的变更上下文
3. **动态评审策略** — 根据变更类型调整评审维度和严格度

## 技术探索：GitNexus — AI 编程的"X光眼镜"

- 定位：零服务器的实时代码地图，通过 Tree-sitter 本地解析构建知识图谱
- 核心 MCP 工具：
  - `impact` — 修改前精确分析影响范围（爆炸半径）
  - `context` — 360° 符号视图，展示完整上下游调用关系
- 成本：**零 Token 消耗**，完全本地离线运行
- 集成：MCP 协议，直接为 AI 编辑器/Agent 提供深度代码感知
- 收益：评审不再只看 diff 片段，能拉出完整调用链和类型定义

## 功能清单

### 1. 评审质量度量
- [ ] Issue 准确率追踪：开发者反馈 issue 是否有效（采纳/误报/部分采纳）
- [ ] 评审分数 vs 实际质量的相关性分析
- [ ] 同一代码多轮评审的一致性指标
- [ ] 质量仪表盘：趋势图、误报率、维度得分分布

### 2. 上下文增强
- [ ] **GitNexus 实时代码上下文** — 零 Token 消耗的代码智能引擎
- [ ] Git blame 信息注入（谁写的代码、什么时候改的）
- [ ] 变更频率分析（热点文件、高频修改区域需更严格审查）
- [ ] 测试覆盖率变化检测（变更是否补充了测试）
- [ ] 依赖变更影响分析（升级了关键依赖时自动标记）

### 3. 动态评审策略
- [ ] 小改动（< 50 行）快速模式：只看安全 + 逻辑
- [ ] 重构类变更：关注接口兼容性 + 测试覆盖
- [ ] 新功能：关注设计合理性 + 边界条件
- [ ] 配置变更：关注安全 + 环境差异

### 4. Prompt A/B 测试
- [ ] 同一 diff 用不同 prompt 版本评审，对比结果
- [ ] Prompt 变更效果追踪
- [ ] 基于历史反馈自动优化 prompt 参数

## 验收标准
- [ ] 评审误报率可量化（目标 < 20%）
- [ ] 质量仪表盘上线，可看趋势
- [ ] 动态评审策略至少支持 3 种变更类型
